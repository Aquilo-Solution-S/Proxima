### Dead Or Stub Tool Surfaces

These core personality tools were registered skeletons returning v1
"not implemented" tool errors:

- `crates/core/src/personality/tools/emit_goal.rs`
- `crates/core/src/personality/tools/search_by_embedding.rs`
- `crates/core/src/personality/tools/walk_lineage.rs`
- `crates/core/src/personality/tools/create_edge.rs`

Classification:
- not accidental private dead functions.
- active declared tool surface.
- remove only if the v1 personality tool catalog should stop advertising
  these capabilities.

Relevant suppressions:
- `#[allow(dead_code)]` on the argument structs is masking schema-only fields
  for these tool declarations.

Implementation direction, 2026-05-15:
- keep the capabilities in the active personality catalog if each can be made
  real without introducing a new runtime registration tier.
- implement and review one tool at a time:
  1. `core/walk_lineage`
  2. `core/create_edge`
- remove the `#[allow(dead_code)]` suppressions as each argument struct becomes
  runtime-read by a real implementation.
- verify each tool against the same gates used for this cleanup:
  `cargo check --workspace --all-targets` and
  `cargo clippy --workspace --all-targets`.

Open design questions for `core/emit_goal`:
- should it write through the core `GoalWrite` verb only, or share the Goal
  flavor helper path that also emits lifecycle Facts and assignment edges?
- should personality-authored goals start as `Proposed` or `Active`?
- how should `inspires_target_self_perspective` and `motivated_by` handles map
  onto `core/inspires` and evidence edges without violating top-down ownership?
- should the tool require Goal flavor schemas, or remain generic over any
  registered Goal payload schema?
- what idempotency key/request id should be derived for wake-local tool calls?

Decision for `core/emit_goal`, 2026-05-15:
- drop `core/emit_goal` from the active substrate personality catalog.
- keep `proxima-goal/goal_propose` as the v1 goal creation surface because it
  writes the Goal flavor lifecycle Fact, `core/inspires`, and motivated-by
  evidence edges.
- do not add a second generic core goal writer under the misleading
  `emit_goal` name.
- leave core ownership of the `GoalWrite` verb intact; this decision only
  removes the unimplemented personality-tool affordance.
